# 技术主路径与整理清单（研发 / 架构）

> 与 **`CLAUDE.md`** 互补：后者是「权威细节」，本文是「一张图 + 清单 + 整理边界」。  
> 整理日期：随仓库迭代更新。

---

## 1. HTTP 主路径（必须牢记）

```
用户 → POST /ai/chat
        → detect_intent（engine/intent.py）
        → execute_workflow_for_chat（engine/workflow_runner.py）
              → collecting 类意图 → run_collecting（engine/collecting.py）
              → LLM 工具：以 meta.meta_tools 为准，当前约定三原子 query_db / submit / ask_user
              → submit → execute_submit → pending_submit_v15b.execute_submit_with_arguments
              → 预览写入 frame.context_snapshot.pending_submit
用户 → POST /ai/confirm
        → run_confirm_execution → workflow_engine_exec.run_confirm_generic_writes
        → 单事务执行 writes（do_insert / do_update / do_soft_delete）
```

**红线**：LLM 不直接连库；一切写库经 tool_executor / 确认引擎。

## 2. 核心文件速查（主路径相关）

| 模块 | 文件 | 职责 |
|------|------|------|
| 入口 | `main.py` | `/ai/chat`、`/ai/confirm`、可选 `session_id`、反馈 |
| 意图与路由 | `engine/workflow_runner.py` | collecting vs run_workflow 分发 |
| 收集 | `engine/collecting.py` | tool 循环、预览、apply_pending_submit_to_frame |
| 工具执行 | `engine/tool_executor.py` | query_db、submit、兼容旧工具执行函数 |
| Submit 组装 | `engine/pending_submit_v15b.py` | workflow_steps → writes；simple/合同归一化 |
| 清洗 | `engine/data_sanitize.py` | sanitize_step_data；必填看 meta.is_required |
| 确认执行 | `engine/workflow_engine_exec.py` | run_confirm_generic_writes；depends 补 contract_id |
| 工作流步骤 | `engine/workflow_steps_util.py` | load_workflow_steps、infer_operation |
